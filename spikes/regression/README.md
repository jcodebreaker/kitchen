# Benchmark regression (2026-11-22): diagnosis and fix

The full benchmark on main 5ba38c6 stopped at ~35/53 correct (66%, `bench/results/2026-11-22-full-claude-main-5ba38c6-partial.md`) against 88% before the W4/W3a-round fixes. Every miss below was read from its job folder (`bench/.work/2026-11-22-11-34-13-full/repos/<ticket>-<n>/.kitchen/`: `job.json`, `ledger.jsonl` refusals, `intake.md`, `spec.md`, `repro-*.json`, `rounds/*/verdict-*.md`, evidence `call.json`), then the same tickets were run once more on main dd02b29 (W5 follow-ups in: `(unchanged)`, the cli wrapper) before any fix: 8/10, the two misses again spec-lint negatives (a-primitive, d-chore-subject).

`node spikes/regression/relint.ts <bench out>…` re-lints every contract a run refused with the current rules: each one of the 5ba38c6 run is now accepted or left to the base check.

## Diagnosis

| class (runs) | root cause | fix |
|---|---|---|
| intake → needs-human, "inline criteria fail spec-lint" (a-chore-1, a-trap-slug-2, b-done-many-1/2, d-chore-subject-1/2/3, d-status-filter-3) | Not a missing repair loop: intake **was** re-run once with the reason (`attempts.refused`, `intake-refused.md`). A negative about what exists **today** (the old "Appearance" heading a rename removes, the old "received" subject, the wrong total) can never be created by an earlier step, so the only honest criterion was refusable. Rule 7 and rule 3 also reported one problem at a time, so the one retry fixed one and met the next. Half of the `(negative)` marks were regression guards ("nothing else changes", "a free slug still works"). | Rule 3 accepts a negative that is (a) made by an earlier step (its text, or a 5+ letter word of what a writing step was given: `cli --argv "add Zebra"` … `not contains "[x] 7 Zebra"`), (b) a value a step of the proof reads and saves (`read --target amount --save amt` then `$amt != "8910"`; `sql … --save b` then `$b not contains "true"`: assert.ts already fails an unsaved, empty, missing or failed one, so it holds only on a real value that differs), or (c) **shown on the base**: anything else goes to the base check, which runs the proof on the base before anything is built (intake now does it for low-risk inline criteria, on the job worktree; spec for its own) and the clause must be FALSE there.
